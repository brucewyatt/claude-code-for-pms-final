ROOK DISPATCH · PRODUCT SCHOOL · CCPM-2026.1

Quiet doesn't
mean forgotten

What went wrong in release 4.2, the evidence for it from six working sessions (each with the exact prompt that produced it), the "way back in" prototype, and the review skill that stops the next brief from shipping with the same gaps.

12 AUG

4.2 shipped. Callout tickets then ran about 3x normal.

THE CAUSE

A shorter ping wait made misses common. A scoring rule that never forgives turned that into silence for four responders.

THE ANSWER

A way back in for quiet responders, and a checklist so the next brief can't skip the basics.

Everything here is a fictional teaching scenario. Responders and handlers are R01–R16 / H1–H15 labels only, per Security Policy 4.1. Press ↓ / space, or use the bar above.

THE SHORT VERSION

What happened with 4.2

Two things changed on one day, and one old design decision turned a bump into a collapse.

7 APR · 4.0
Console nav, profile redesign, routing-override audit log.
16 JUN · 4.1
Proximity uses travel-time estimate; bulk callout; push reliability.
12 AUG · 4.2
Proximity weighted up, recent-acceptance weight 0.40 → 0.25 (not in release notes), ping wait 90 → 60 s.
17 AUG →
"Phone never goes off" tickets begin and keep growing into September.

The loop that kept people quiet

Shorter wait → more missed pings
→
A miss costs 0.12, same as a decline (history.py)
→
Lower score → fewer pings
→
Score only rises on a taken ping (+0.08)
↺

Nothing decays the score (a 2019 TODO was never built), so being quiet is what keeps someone quiet.

The numbers, in one glance

A step on the release day, not a drift. Includes the 90→60 s change; the table has no response times, so the wait cut isn't isolated from delivery.

Source: 04-x-ray-vision/prompts.md. Working hypothesis: the 60 s wait made misses common; "miss = decline, never decays" turned that into silence for a subset. The weights amplify, they aren't the root cause. Fix order: measure first, then change one variable at a time.

Quiet doesn't mean forgotten.

Responder

Plain-language check-in instead of silence, a one-tap "I'm ready", then a bounded number of re-entry offers on nearby callouts so a good answer can pull rank back up.

Handler

A "gone quiet" marker on the responder card with the reason split out. Confirm they're ready, or flag a phone problem.

Underneath

A missed ping is scored lighter than a turned-down one. Silence stops being treated as a verdict. A miss still costs something, just less.

Does not: revert 4.2, change the ping wait or weights, promise callouts, change current_record() (Supply reads it), or identify anyone. Still open: sent vs delivered, how production stores scores, and the out-of-area pings.

MODULE 6 · SIDEKICKS

Turning a habit into a skill

The briefs around 4.2 failed in predictable ways. So the review I do by hand became a reusable skill.

ARTIFACT · THE SKILL

.claude/skills/review-checklist/SKILL.md: six checks, always in the same order, with a Pass / Partial / Fail table, a quote for each, and the smallest fix.

I want to save a habit as something I can reuse. When I review a brief before it goes any further, here's what I actually check for: * It names who owns it * It says how we'll know it worked * The scope at the end matches the scope at the start * It explains the problem before it proposes a fix * It cites a data point and data source, which can be a number, verbatim, or some other form. Make sure it cites its source * It explains why the problem matters, and what success looks like Turn that into a skill called review-checklist, so I can point it at any brief and get the same check every time, without me explaining it again.

Source: 06-sidekicks/prompts.md prompt 1.

THE GUARDRAIL

How the skill stops a repeat

4.2 shipped with a cut to a ping wait nobody tested alone, a weight change not in the release notes, and a roadmap item still marked Committed after it slipped. Each of those is a gap the checklist is built to catch before a brief goes further.

HONEST LIMITS
  • A checklist catches gaps in a brief. It doesn't prove the cause: sent vs delivered, Wen Li's intent and production score storage are still open.
  • It won't stop a change that never gets a brief. The rule that no config.py change happens without Marcus still matters.
